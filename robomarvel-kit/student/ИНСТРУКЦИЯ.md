# Ученическая среда Robomarvel: развернуть и запустить

Этот файл описывает, как из папки `student` создать на компьютере рабочую среду для курса: контейнер `robomarvel-sim`, VS Code в браузере и папку курса, в которой ученик будет писать код.

Команды выполняются в двух местах: на самом компьютере (терминал PowerShell на Windows, Terminal на macOS и Linux) и внутри контейнера. Ниже явно указано, где именно.

## Быстрый запуск скриптом

Шаги 2-4 можно выполнить готовым скриптом. В папке `student` для Windows PowerShell:

```powershell
.\run-container.ps1
```

Если Windows не дает запускать файлы `.ps1`, обойдите политику так:

```powershell
powershell -ExecutionPolicy Bypass -File .\run-container.ps1
```

Скрипт загрузит образ (если его еще нет), создаст и запустит контейнер `robomarvel-sim`, терминал останется внутри контейнера. Для Linux и macOS: `./run-container.sh`.

Ниже те же действия описаны по шагам вручную.

## Шаг 1. Установить и проверить Docker

Установите Docker Desktop (Windows, macOS) или Docker Engine (Linux). Затем проверьте в терминале компьютера:

```powershell
docker --version
docker info
```

`docker --version` печатает версию клиента. `docker info` печатает сведения о системе и работает только тогда, когда сам Docker запущен. Если вместо этого приходит `Cannot connect to the Docker daemon`, откройте Docker Desktop и дождитесь зеленого статуса либо на Linux выполните `sudo systemctl start docker`.

## Шаг 2. Загрузить образ

Файл образа положите на флешку или диск. Для обычных компьютеров на Intel и AMD это `robomarvel-sim-amd64.tar`, для Mac на процессорах Apple M1 и новее - `robomarvel-sim-arm64.tar.gz`.

В терминале компьютера перейдите в папку с файлом образа и выполните:

```powershell
docker load -i robomarvel-sim-amd64.tar
```

Команда понимает и обычный архив `.tar`, и сжатый `.tar.gz`, распаковывать заранее не нужно. Ожидаемый вывод: `Loaded image: robomarvel-sim:latest`. Проверка:

```powershell
docker image ls
docker image inspect robomarvel-sim:latest --format "{{.Architecture}}"
```

В списке должна быть строка `robomarvel-sim`, а вторая команда печатает ту же архитектуру, что и `docker version --format "{{.Server.Arch}}"` на этой машине.

## Шаг 3. Разложить папку курса

Скопируйте папку `student` на компьютер под именем `robomarvel` в домашний каталог:

- Windows: `C:\Users\<имя пользователя>\robomarvel`
- macOS: `/Users/<имя пользователя>/robomarvel`
- Linux: `/home/<имя пользователя>/robomarvel`

Внутри должны лежать `Dockerfile`, `colcon-defaults.yaml` и пустая папка `packages`. В `packages` за курс ляжет весь код робота, который напишут ученики.

## Шаг 4. Запустить контейнер

Откройте терминал компьютера, перейдите в папку `robomarvel` и выполните:

```powershell
docker run -it --name robomarvel-sim -v "$(pwd):/src" -p 127.0.0.1:8765:8765 -p 127.0.0.1:8000:8000 -p 127.0.0.1:8554:8554 -p 127.0.0.1:8889:8889 -p 127.0.0.1:8189:8189/udp robomarvel-sim
```

Приглашение сменится на `student@<номер>:/src$`. Это терминал внутри контейнера, он же пульт управления роботом на весь курс. Не закрывайте его до конца работы.

Разбор команды:

- `docker run` - создать и запустить новый контейнер из образа;
- `-it` - сделать терминал интерактивным;
- `--name robomarvel-sim` - дать контейнеру имя;
- `-v "$(pwd):/src"` - подключить текущую папку компьютера внутрь контейнера как `/src`;
- `-p 127.0.0.1:8000:8000` - открыть порт 8000 для VS Code в браузере;
- `robomarvel-sim` в конце - имя образа.

Важно запускать команду именно из папки `robomarvel`: подключается та папка, в которой вы находитесь.

## Шаг 5. VS Code в браузере

Откройте в браузере http://localhost:8000, подождите 20-30 секунд и обновите страницу, если она еще не открылась. В меню File выберите Open Folder, укажите `/src` и подтвердите доверие авторам.

Файлы, которые вы здесь создадите, лежат в папке `robomarvel` на компьютере.

## Шаг 6. Первые команды

В терминале контейнера выполните:

```bash
pwd
ls
ls packages
```

`pwd` показывает текущую папку, ожидаемый ответ `/src`. `ls` показывает содержимое: `Dockerfile`, `colcon-defaults.yaml`, `packages`. `ls packages` пока ничего не выводит, папка пуста.

## Сборка проекта

Когда в `packages` появится код, его собирают так:

```bash
cd /src
colcon build
source /src/install/setup.bash
```

`colcon build` собирает пакеты, `source` подключает их к текущему терминалу. Команду `source` нужно повторять в каждом новом терминале. В контейнере есть сокращения: `ws` - перейти в `/src`, `cb` - собрать проект, `cs` - подключить собранные пакеты.

## Второй терминал

Чтобы открыть дополнительный терминал в уже запущенном контейнере, выполните на компьютере:

```powershell
docker exec -it robomarvel-sim bash
```

В новом терминале снова выполните `source /src/install/setup.bash`. Выход из дополнительного терминала командой `exit` контейнер не останавливает.

## Остановка и повторный запуск

Выход из главного терминала командой `exit` останавливает контейнер. Остановить его снаружи можно так:

```powershell
docker stop robomarvel-sim
```

Снова запустить уже созданный контейнер и вернуться в его терминал:

```powershell
docker start -ai robomarvel-sim
```

Команда `docker run` создает контейнер один раз. Дальше его только включают и выключают.

## Частые проблемы

- `Conflict. The container name "/robomarvel-sim" is already in use` - контейнер уже создан. Не создавайте второй, используйте `docker start -ai robomarvel-sim`.
- `Bind for 127.0.0.1:8000 failed: port is already allocated` - порты заняты другим контейнером. Проверьте `docker ps` и остановите лишний, например `docker stop robomarvel-demo`.
- `Package 'robomarvel_sim' not found` - не выполнен `source /src/install/setup.bash` в этом терминале либо не сделан `colcon build`.
- `exec format error` сразу после запуска - загружен образ другой архитектуры, возьмите файл под свою машину.
- `http://localhost:8000` не открывается - контейнер не запущен либо VS Code еще стартует, проверьте `docker ps` и обновите страницу.
- `ls packages` в папке курса что-то показывает не то, что ожидалось - проверьте `pwd`, вы можете находиться не в той папке.
